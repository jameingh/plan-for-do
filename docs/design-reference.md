## 0. 实拍校正：CSS 猜不出来的东西

看了真界面，之前从 CSS 推断的几处是错的，以实拍为准：

| 之前以为 | 实际是 |
|---|---|
| 左侧 200px 信息栏（清单本/分组/分类/标签） | **~72px 纯图标竖栏**：头像在最上，下面 清单/视图/习惯/备忘录 四个「图标+两字」项，当前项绿色 |
| 分组方式是左栏里的按钮组 | **主列顶部的文字页签**「日期 / 分类 / 四象限」，当前项绿色 + 下方 2px 绿色短横线 |
| 一个列表纵向排四个桶 | **多列并排**：逾期一列、未打卡一列，各列独立滚动，列头是「名称 + 绿色计数」，右侧绿色文字链「顺延到今天」 |
| 事项是一行行列表项 | **白色卡片**：圆角 ~8px、浅阴影、内边距宽松，卡片间距 8–12px；子任务缩进在父卡片内部，各自带勾选框，父项显示「0/4」与折叠箭头 |
| 勾选框是圆形 | **圆角方形**（约 16px，琥珀/橙色描边，未填底） |
| 行高 44–48px 紧凑 | 实际**偏松**：单条卡片 ~56px，靠卡片留白而不是压缩行高来组织密度 |
| 新建入口是输入框 | 每列底部一张**大号「+」白卡片**作为新建入口 |
| ~~页面最底部一条绿色进度条~~ | **更正（2026-11-07）**：参考站底部那条绿色是它的**横向滚动条**（`ul.group-items::-webkit-scrollbar{height:.1rem}` + 绿色渐变胶囊 thumb），不是完成度进度条；实测视口底部没有任何进度元素 |

## 0.2 三张实拍的硬结论（图已删除，结论与数值保留在下方）


**01 清单·日期**：主区是**多列并排**——「逾期 1」「未打卡 5」各占一列，列头是名称 + 绿色计数，
「顺延到今天」是列头右侧的绿色文字链；每条事项是一张**白色卡片**（圆角 8、浅阴影、内边距宽松），
勾选框是**橙色实心小方块**（§9.2 实测 11×11 `#ff9e00`，此前我记成描边圆角方形）；子任务缩进在父卡片内部、各自带勾选框，父项显示「⌄ 0/4」；
每列底部一张大号「+」白卡片；页面最底部那条绿色是**横向滚动条**（不是进度条，见 §17）。

**02 清单·四象限**：不是四个平铺分组，而是 **2×2 象限卡片**——
每象限一张大卡，头部是「Ⅰ 重要且紧急」这样的**罗马数字 + 名称，四象限各有各的颜色**
（Ⅰ 红、Ⅱ 橙、Ⅲ 蓝、Ⅳ 绿），右上角一个同色「+」；
卡片内部再按状态折叠子组（「⌄ 已打卡 12」「⌄ 未打卡 5」「⌄ 逾期 1」「⌄ 待办 2」），
子组头 12–13px 灰字，行内是勾选框 + 标题 + 「打卡时间：10月07日 08:54」+ 右侧铃铛图标 + 分类小圆点与名称。

**04 习惯**：顶部是一排**日期卡片**（每张约 76px 宽，三行：「10月」12px 灰 /「20」20px 粗 /「周二」12px，
圆角 8、1.5px 描边；**选中或今天 = 绿色描边 + 绿色文字**，其余灰），横向可滚；
下面是**情境折叠组头**（「晚间 1 ⌄」，不是分段 tab）；
每条习惯一张大卡：左侧 **44px 圆形图标底**（图标色板偏暖，实拍里是珊瑚红/西瓜红，不是绿色系）+
标题 15px/500 + 「累计打卡8天」12px 灰 + **横向圆点切片**（20px 圆，未打卡浅灰底灰字、
**今天 = 红色实心白字**、未来更浅）。注意：切片是跟着顶部选中的那天左右展开的连续日期，不是月历网格。

## 1. 它的原生设计系统

参考站 CSS 里定义的变量（原样抄录）：

```css
--color-normal:      #03a17e;              /* 主绿 */
--color-deep:        rgba(3,161,126,.1);   /* 主绿 10% */
--color-shallow:     rgba(3,161,126,.05);  /* 主绿 5%  */
--color-normal-tip:  #fc6a7a;              /* 对应粉红，用于提醒/待完成 */
--color-deep-tip:    rgba(252,106,122,.1);
--color-shallow-tip: rgba(252,106,122,.05);
```

**这就是它的语言**：一个绿、一个粉红，各自三档浓度（实色 / 10% 底 / 5% 更浅底）。
选中态不是「边框变蓝」，而是「底色变 5–10% 的主色 + 文字变主色」。

其它实测频率统计：

| 用途 | 值 | 出现次数 |
|---|---|---|
| 主文字 | `#333` | 246 |
| 次级文字 | `#999` | 178 |
| 反白 | `#fff` | 112 |
| 分隔线 | `#eee` / `#eeeff1` | 67 / 48 |
| 中间文字 | `#666` | 62 |
| 页面底 | `#f6f7f8` / `#f9f9fb` / `#f0f0f0` | |
| 警示红（逾期） | `#e13e39` / `#fe4a4a` | |
| 圆形元素 | `border-radius: 50%` | 57 |
| 阴影 | `0 .04rem .15rem rgba(0,0,0,.1)`（卡片）、`0 6px 30px rgba(3,161,126,.3)`（主色发光） | |
| 字体 | `PF-Regular` / `PF-Medium`（商用字库，本项目用系统栈替代） | 287 / 117 |

它的 CSS 用 rem，因为 Web 端是移动优先；本项目是桌面壳，落到 px，但**颜色与层次照抄**。

## 2. 本项目的 token（`styles/global.css` 必须只用这些）

```css

  --brand-deep: rgba(3,161,126,.1);
  --brand-shallow: rgba(3,161,126,.05);
  --brand-glow: 0 6px 24px rgba(3,161,126,.22);

  /* 对应色：粉红（提醒、未完成、需关注） */

  --alert-deep: rgba(252,106,122,.1);
  --alert-shallow: rgba(252,106,122,.05);

  /* 逾期用更重的红，与「需关注」区分 */

  /* 中性 */
  --text: #333;
  --text-2: #666;
  --text-3: #999;
  --bg: #f6f7f8;
  --surface: #fff;
  --surface-2: #f9f9fb;
  --line: #eeeff1;

  /* 圆角：卡片 10、控件 8、胶囊 999、图标底 50% */
  --r-card: 10px; --r-ctl: 8px; --r-pill: 999px;

  /* 间距：4 的倍数，密度优先 */
  --s1: 4px; --s2: 8px; --s3: 12px; --s4: 16px; --s5: 24px; --s6: 32px;

  /* 阴影只用两级，别叠第三级 */
  --shadow-1: 0 1px 3px rgba(0,0,0,.06);
  --shadow-2: 0 6px 24px rgba(0,0,0,.08);

```

暗色主题只改中性层（`--bg/--surface/--line/--text*`），主色不动。

## 4. 交互规范（2026-11-06 按 §11 取证校正；早期凭印象写的动效已作废）

1. **勾选打卡**：11×11 方框、无圆角。**未勾选空心**（橙色描边 + 透明底，用户明确要求，覆盖参考站的实心读数）；
   hover 出现橙色浅底；成功 = 灰底白勾，**失败 = 提醒色底白叉**（参考站右键有「成功打卡/失败打卡」，
   失败是一等状态）。**没有描边动画**——参考站这里 transition 为 0s，瞬时切换。
2. **行的可操作性**：整行 hover 换**主色浅底**（日期模式 `--brand-deep` .1，分类/象限 `--brand-shallow` .05），
   右侧动作图标淡入（用 opacity，不占位不抖动）；动作还有**右键菜单**（见 4.11）。
3. **选中项**：左侧 inset 主色描边，不是整块变蓝。
4. **分组折叠**：箭头与内容**即时**切换（参考站无过渡）；折叠状态按「日期:组」记忆，切日期不丢。
5. **即时保存**：字段改完失焦即写库，右上角出现极轻的「已保存」脉冲。新建表单例外：改动只进草稿，
   点「保存」或标题栏回车才落库（参考站的新建弹窗就是保存/取消收尾）。
6. **空状态**：一句话 + 一个动作，居中，`--text-3`，12px。不要插画、不要 emoji 堆砌。
7. **错误**：内核返回的中文错误直接显示在触发的控件下方，12px `--overdue`；
   全局错误才用 toast，toast 出现在底部居中，深色底白字，3s 自动消失，可点关闭。
8. **键盘**：`Enter` 新建/保存、`Esc` 关最上层浮层（详情/新建/右键菜单/模态框共用一个栈）、
   `Space` 勾选当前行、`↑↓` 在行间移动、`1..4` 切组。焦点环用 `--brand`，2px，只在 `:focus-visible` 出现。
   参考站本身没有快捷键（只有 Element 的 Esc 关弹窗），这套是我们加的，不冲突就保留。
9. **习惯月切片**：15px 圆形，`未打卡=--hdot-off-bg 灰底`、`已打卡=--brand 实心`、
   `部分=--brand-shallow 底 + --brand 描边`、`今天=--alert 红底`、`未来=--surface-2 无描边`；
   **今天没打卡是 `pending` 而不是 `missed`**，悬停放大 1.15 倍。
10. **过渡时长**：只有两档动效——弹窗 `300ms ease`（从上方 20px 落下 + 淡入）、
    视图切换 `300ms cubic-bezier(.55,0,.1,1)` 淡入。列表区一律 0s。
    chrome（页签、按钮、齿轮）保留 120ms 微过渡，那是 Element 控件自带的。
11. **右键菜单**（参考站的一等交互）：卡片 = `置顶 / 编辑 / 删除`；勾选框 = `成功打卡 / 失败打卡 /（已结清时）取消打卡`；
    详情右上 `⋯` = `置顶 / 删除清单`。菜单落在鼠标点，贴边自动翻转，透明遮罩点任意处或 Esc 关闭。

要点：

- **多列并排**是这套界面的骨架：每个桶一列，列宽 ~260–360px，列间留白而不是分隔线。
  事项少的时候只有一两列，不要为了填满而拉伸。
- 列头：`13px/500` 名称 + 绿色计数；右侧动作是**绿色文字链**（不是按钮）。
- 卡片：`--surface` 底、`--r-card` 圆角、`--shadow-1`、内边距 `12px 14px`、卡片间距 8–10px。
  **阴影只给卡片**，浮层/菜单/toast 用 `--shadow-2`。
- 详情面板：点卡片后从右侧滑入 320px，遮罩不加（保持多列可见），窄屏 <900px 收成浮层。
- 图标栏：44px 图标 + 11px 两字标签，当前项 `--brand`，其余 `--text-3`；顶部头像 32px 圆形。
- 清单本/分类/标签这些**筛选**放在列头上方一条 32px 的工具行里（下拉或胶囊），
  不再占用左侧——左栏只承担一级模块切换。

## 16. 提醒面板与「自定义提醒时间」（2026-11-07 从 bundle 取证，未点击参考站任何控件）

用户反馈：自定义提醒时间点了不生效，交互也和参考站不一样。这次没有再点参考站的界面（它的字段是即时保存的，

### 16.1 bundle 里的真实结构

- `.body-remind`（列表面板）= `.custom-time`「自定义提醒时间」入口 + `ul.items`（第一项 `无提醒`，
  其 `item-selected` 绑的是 `remindCount === 0`，即**没提醒时无提醒自己打勾**）+ `.bottom-button`。
  按钮是 `float:right`，DOM 里 保存 在前、渲染后 保存 仍在最右，与我们 `PanelButtons` 的 清除→取消→保存 等价。
- 多选：`currentItems` 每条自带 `state`，`selectRemind` 点一下翻一条（不是替换），
  非会员 `remindCount>=2` 时弹付费框，硬上限 `remindCount<5`；`cancelRemind`（点无提醒）把**所有** state 清掉。
- `.body-custom-time`（自定义子视图，宽度 3.08rem vs 列表 2.42rem）= `.title` +
  `.scroll-box`(`.scroll-day` + `.scroll-hour` + `:` + `.scroll-minute`) + 取消/保存。
  只有时时分之间有分隔符，日与时无；日列 `flex-basis: content`；`li.scroll-item{height:20%}` → 一屏 5 行。
- 数据源 `getMyData(2)` = **今年全部日期**，文案 `11月7日周五`（月日都不补零）；`getMyData(0/1)` = 00..23 / 00..59。
- `saveTime({day,hour,minute})`：从日列文案里抠出月日 → `addZero` →
  `text = "11月07日 09:30"`、`remindDate = "YYYY-MM-DD HH:MM:00"`，push
  `{advanceDay:0, advanceHour:0, advanceMinute:0, remindDate, remindTime:"", remindType:2, state:true}`；
  同 text 已存在则只置 state，不重复加。
- 芯片/字段行文案 `initRemind`：remindType=2 → `MM月DD日 HH:MM`（补零、中间一个空格）；
  remindType=1 → `当天(09:00)` / `提前N天(09:00)`；type=0 → `准时`/`提前N天M小时K分钟`。
  多条就是 `text += t.text + ","` 再抹掉尾逗号——**逗号拼接，不折叠成「N 条提醒」**。

### 16.2 我们错在哪

1. 自定义做成了「提前 N 天 M 时 K 分」三个数字框（参考站是月日+时分滚轮的绝对时刻）；
2. 面板只能留一条提醒，加完自定义不打勾、不进列表，点保存像什么都没发生 ——「不生效」的观感就是这么来的；
3. 芯片只渲染 `reminders[0]`，第二条以后在界面上不可见；
4. 内核侧绝对提醒跟着事项实例走：重复事项每天展开一次就重放一次，**没日期的事项干脆一条都不报**。

- `RemindPanel` 重写：多选列表（无提醒=清空）+ 三列滚轮子视图（全年日期/时/分，默认停在今天 09:00）+

## 17. 时间默认值与底部那条绿色（2026-11-07）

### 17.1 默认当前时间（bundle 取证）

- `TimeModule.mounted`：`timeType` 为 **0（没设）或 3（全天）** 时
  `point = {state:true, hour: addZero(now.getHours()), minute: addZero(now.getMinutes())}`
  —— 打开面板滚轮就停在**当前时分**并按「时间点」起步；timeType=1/2 才回填已存的起止。
- `CustomDate.mounted`（提醒的自定义滚轮）同理：默认 **今天 + 当前时分**，不是硬编码 09:00。
- 我们的 bug 在 `TimePanel` 的解析：`(""/undefined).split(":").map(Number)` 得到 `[0]`，
  `Number.isFinite(0)` 又为真，于是小时退回不了默认值 —— 实测 17:28 打开面板是 **00:28**
  （分钟因为解析成 `undefined` 才侥幸退回默认，所以现象是「时错分对」这种怪组合）。
  改成空值整体退回默认；提醒滚轮同样按当前时分起步。
- 顺带对齐 `submitTime`：时间段起止相同时按**时间点**落库，不留零长度区间。

### 21.1 参考站的真实结构（决定我们怎么写的几条）

- rem 基准是 `parseInt(innerWidth/1920*100)`，1025px 窗口下 1rem=53px。**只有比例可迁移，绝对 px 不行。**
- 三个视图共用一套「天对象」`dayItems[i] = {matters, hourMatters, crossMatters, habits}`，
  分流规则原文：`("month"===viewType || 1!==clockTimeType && 2!==clockTimeType) ? matters.push(n) : hourMatters.push(n)`
  —— 月视图把带时刻的事项也画成彩条，周/日把带时刻的送进小时网格，全天区只留全天/跨天。
- 全天区固定 **2 行**：`setChainItems(dayItems, [], 2)`。行0 = 真实条，行1 = `createCountChain` 的「还有 N 个任务」
  （`viewColor:#F6F7F8`）。计数 = 当天 matters（按打卡过滤）+ 从更早日期延伸进来的跨天数 + habits − 行0 已显示条数。

- 折叠：`upFoldIndex/downFoldIndex`，hover 小时轴才出现 ↑↓，**中间 10~13 点是安全带不给折**；
  折叠行是网格的兄弟节点（`.row-up/down-fold-hour`，整宽、`height:1rem`、左轴 `#f6f7f8`），

### 21.4 这轮被自检抓出来的四个真问题

1. **周/日全天区混进带时刻事项**：`rowBars` 没按 `time.kind` 分流，早会/评审同时出现在全天区和小时网格，
   「还有 N 个任务」还多算了两条。按参考站的 `matters`/`hourMatters` 分流补上。
2. **`--hour-h` 是 `clamp()`**：`parseFloat(getComputedStyle(el).getPropertyValue("--hour-h"))` 只会读到
   字符串开头的 `56`，初始滚动位置偏小到真实值的 53%。改成量渲染出来的小时行高。
3. **折叠行写在 `.vw-hours` 里**：右侧列层 `.vw-cols` 是定位元素，把「展开」按钮整个盖住
   （`elementFromPoint` 命中的是 `.vw-col`），并且列层与小时行错位一个折叠行高。
   参考站的折叠行本来就是网格的兄弟节点 —— 改成整宽行后，点得到、也对齐了。
4. **头像菜单的透明遮罩是 `.rail` 的子节点**：同一个层叠上下文里，定位元素永远压在静态的模块按钮上，
   菜单开着点模块只关菜单不切页。给 `.rail.is-menu` 里的头像与模块按钮显式抬 `z-index`。
   （这条是视图把模块栏从 3 个加到 4 个之后，`check-account.mjs` 才暴露出来的。）

### 21.5 有意偏离（按「参考某软件 = 功能+交互+视觉」的口径，逐条标注）

- 月格泳道固定 3 + 1 计数行，不按格子高度实时算 `chainCount`；窗口再高也只是多留白。
- 全天区行0 用「一列一条」的贪心装法；参考站是「每天第一条事项 + 第一个习惯」并允许同列重叠。
  我们避免重叠，代价是同列的习惯条可能被挤进「还有 N 个任务」。
- 折叠后不做坐标系平移（参考站 `155*(up+1)`），直接只渲染未折叠的小时行，视觉等价、少一处算错的机会。

### 23.1 内核：四个页签共用一个区间接口

`internal/core/service/habit_stat.go`（236 行）只出一个 `HabitStat(ctx, {start,end})`，
日/周/月/年四种切法全在这一处聚合——不然「日统计的完美打卡百分比」和「周统计的完美打卡天数」迟早会算拧。
`api.go` 里 `API.HabitStat` 是薄壳（只兜 nil 切片，免得 JSON 出去变 `null` 让前端 `.map` 崩）。

三条定义先钉死（写进文件头注释，Go 测试逐条锁住）：

- **打卡（checked）**：那天有记录且量 > 0。多次习惯没打满（3/8 杯）也算打了卡；
  回溯额度允许往**非排期日**打卡，那种天照样算打卡、格子照样变红。
- **打满（done）**：那天的量 ≥ 当日目标（每天一次的习惯就是 1 次）。
- **完美打卡**：某天**应打的习惯全部打满**。应打 = 那天在排期里且习惯已开始，不含未来天。

格子状态机出六态 `done | partial | pending | missed | rest | future`，判定顺序有讲究：

```go
case amt >= target && target > 0: "done"        // 打卡优先于排期：
case amt > 0:                     "partial"     // 补打落在非排期日时，
case !due:                        "rest"        // 不能因为排期表里没有就把
case repeat.DiffDays(today, d) > 0: "future"    // 用户已经打过卡的那天画成休息——
case d == today:                  "pending"     // 吞掉记录比多出一格更糟
default:                          "missed"
```

- 前端把六态压成用户要的三色：`done|partial → 红`、`missed|pending → 灰`、`rest|future → 浅灰`。
- `Done` 只在**应打日**计数，所以额外补打不会把当天算成 `Done > Scheduled` 的假完美。
- 连续天数按「天」这条横切面算：当天有打卡就续上；未来天既不断也不续；已过完且应打未打才断。
  这三条分支都要留着——少了「未来天不续」会提前报连击，少了「应打未打要断」整月没打卡也能报出假数字。
- 区间校验：起终反了报「统计区间反了」，超过 380 天报「统计区间过长（最多一年）」。年页签正好一年，留了闰年余量。
- `repeat.DiffDays(a,b)` 是 **b−a**（b 晚于 a 为正）。这个方向在本次实现里写反过两次（区间校验和未来态判定），
  都是 Go 测试当场抓的——新增 `TestHabitStat*` 六条：日状态机、完美日、周网格含休息格、年区间与未开始习惯、
  半量算打卡、**非排期日补打仍算打卡**。

## 24. 专注模块：正计时 / 番茄钟 / 倒计时 + 数据页（2026-11-08）

用户要新增一个一级模块「专注」，三个子模块都能关联任务，另有一个数据页（统计分析 + 数据分布）。
**参考站没有这一模块**（朝暮 Web 只有清单/视图/习惯/备忘录四个一级模块，§22.1 已记），
所以视觉基准走的是「照用户书面规格 + 本项目既有界面语言」，本轮**没有**对参考站做任何新动作。
四个口径问题在开工前问过他，答案都落进了实现：三样数据（趋势/类型占比/任务排行）都要、
进行中落内核重启回到那一次、番茄休息不计时长。

### 24.1 内核：一条记录 + 一个区间聚合

`internal/core/model/model.go` 加 `FocusRecord / FocusPlan / FocusEvent`，
`store.KindFocus = "focus"` 进 `AllKinds`（同步引擎、`stats`、飞书通道每 kind 自动一张表，白拿），
派生列 `day = 归属日`、`parent = 关联事项或习惯`、`status = 记录状态`。

`internal/core/service/focus.go`（约 700 行）是唯一口径来源，界面不自己算：

- **计时账本 = `AccumSec` + `SegmentStart` 两段**，不是「结束时算一次差值」。
  理由：应用被关掉/崩溃的那段时间不能算专注。前端每 30 秒 `FocusTick` 把走满的一段折进累计，
  所以崩溃最多丢一个心跳周期；`FocusRecover` 重启时也只按 `focusRecoverGrace = 30` 秒补一段，
  然后**强制停在暂停态**等用户决定继续还是结束——不会偷偷替他计时。
- **`SegmentStart` 只在专注阶段非空**：`FocusRestStart` 进休息时先折一次再清空段起点，
  于是「休息中关掉应用」恢复出来也不会多出一段假专注。休息秒数单独进 `RestSec`，只展示，不进 `ActualSec`。
- **`RoundBase`（本轮开始时的累计）** 是番茄钟算本轮剩余的分母。这个字段是自检抓出来的：
  没有它，第二轮的剩余拿全程累计去减，一休息完就「已超时」，整个番茄一路自动冲到最后一轮
  （`TestFocusPomodoroRestNotCounted` 现在锁着 `RoundBase == AccumSec`）。
- **一次只允许一条未结束的记录**（`FocusStart` 报「已有专注进行中，请先结束或放弃」）：
  计时器是独占的，两条并行既没法同时沉浸，也没法在统计里说清哪一段算数。
- **`放弃（不保存）` 写同步墓碑**而不是硬删——这条可能已经同步到另一台设备。
- **补记（`Source = FocusManual`）不伪造起止时刻**：`StartAt/EndAt` 留空，归属日就是用户选的那天。
  所以它进得了总时长、进得了每日趋势与年热图，但**进不了「时段 × 星期」矩阵**；
  矩阵放不下的部分内核单列 `UnplacedSec / UnplacedCount`，界面把这句话原样写出来，不装作没看见。
- **实时记录的事实字段不可改**：`FocusSave` 对 `Source = live` 的记录只认心得与关联任务两处改动，
  时长/日期/类型改了等于伪造历史；补记记录整条可重写（它本来就是手填的）。
- 关联任务事项与习惯**二选一**（同时传报错），ID 存在性都查；
  任务名**不在记录里存副本**，`FocusGet`/`FocusList` 现取（事项改名不用回写历史）。
- `FocusCandidates` 的「全部待办」直接复用 `ListView` 的逾期/今天/往后三桶，
  不再另写一套「什么算没做完」；传了具体某天则**严格只看那一天**（逾期项不混进来）。
- `FocusStat(start,end)`：`overview` 是全历史的（用户要的「累计专注」不能变成「这个月累计」），
  `daily / byType / byTask / matrix` 按区间；区间校验与习惯统计同一套（反了报错、超 380 天报错）。
- Go 测试 8 条：开始/暂停/继续/结束全链、放弃写墓碑、崩溃区间被夹住、番茄休息不计时、
  补记校验（未来/0 秒/超 24 小时都拒）、实时记录事实字段不可改、聚合数字逐格对、候选按天严格筛。

### 24.2 界面

模块栏加「专注」（清单/视图/习惯/专注/备忘录/设置，Ctrl+1..6），`PLANDO_START_TAB` 白名单同步加 `focus`。
`frontend/src/components/` 拆成 `FocusPage`（外壳）/`FocusPicker`（关联任务）/`FocusWheel`（分钟滚轮）/
`FocusImmersive`（沉浸 + 结束确认 + 结算）/`FocusDetail`（详情）/`FocusData`（数据页），
共用算式在 `frontend/src/lib/focus.ts`（时长人话、番茄轮次推进、默认配置）。

- **三个子模块的行结构按规格**：关联任务 → 计时器/分钟滚轮 →（番茄多一行「番茄设置」）→ 开始专注。
  每个页签各留一份关联任务，切页签不串。已关联的显示在子模块标题位，再点给出「更换任务 / 清除任务」。
- **关联任务弹窗**：标题位就是日期选择器（默认「全部待办任务」），点开是日历，三键**清除/取消/保存**
  ——直接复用事项面板的 `DatePanel`，给它加了第三个 `variant="day"`（只要单日、但保留「清除」，
  清除 = 回到全部待办）。第二行两页签：待办事项清单（默认）/ 习惯打卡。
- **沉浸页**：整窗只有一颗大时钟在走，右上 × 退出（专注继续进行中），下方暂停 → 继续/结束，
  左下角「专注详情」。结束弹窗标题「当前专注进行中」，三行按钮 结束（保存记录）/放弃（不保存）/取消；
  保存后进「专注目标达成」结算页，带心得输入框与左下角详情入口。
- **番茄钟**：`FocusPlan` 是每次开始时的配置快照（个数 4 / 短休息 1 分 / 长休息 2 分 / 每 4 轮长休息 /
  自动开始休息默认开），改设置不回溯历史记录。轮次推进：一轮专注走完 → `FocusPhaseEnd("focus")` 记轮数 →
  `FocusRestStart` 进休息 → 休息走完 → `FocusPhaseEnd("short"/"long", 秒)` → `FocusResume` 开下一轮；
  最后一轮专注结束直接结算，不再补一次休息。自动休息关掉后，每个阶段边界都停下等用户按。
- **分钟滚轮**（`FocusWheel`）：圆圈里 `scroll-snap` 的分钟列，能滚、能拖、能点，落定后 140ms 提交。
  仓库里原有三份私有滚轮只认点击，且已被别的自检脚本测过，所以没去改它们。
  列表上下各垫 `(visible-1)/2` 格空格，选中的那一格才真能停在圆心——不垫的话第一格只能贴到顶，
  而正中显示的是「选中项的下一格」（2026-11-08 用户指出「25 在上面、26 在中间」）。
  垫了之后 `scrollTop = index × 行高` 正好让第 index 格居中，取值的反算也简单。
  自检里三条几何断言锁住它：默认值居中、滚到顶第一格居中、滚到底最后一格居中（±2px）。
- **数据页 · 统计分析**：数据总览（累计专注 时长/次数 + 右箭头进历史列表；今日专注 + 右箭头进今日列表；
  列表项右箭头进专注详情）→ 补记专注记录按钮（进补记页：标题 + 右侧保存 + 三类型页签）→
  专注时长分布（>60 天自动按月聚合的柱 + 三类型占比条）→ 全时段热图（一年日历，深浅四档）→
  专注时长分解（168 格时段×星期矩阵 + 任务排行 + 补记不进矩阵的交代）。
- **数据页 · 数据分布**：日统计（四个数 + 24 根小时条 + 当天记录）/ 月统计（四个数 + 按星期对齐的月格热图）/
  年统计（三个数 + 全年趋势与类型分布），三块各自带左右翻页且都不许越过今天。
- **内容区版式（2026-11-08 按反馈调）**：四个页签的内容都在 `.fc-scroll` 里，用 `margin: auto` 居中——
  不用 `justify-content: center`，因为 flex + overflow 的容器里那样会把超出视口的顶部**裁到滚不到**；
  auto 外边距是「不满一屏才居中，满一屏正常从顶部排」。`.content` 自己是 `overflow: hidden`（各页自带滚动区），
  所以数据页必须包这一层能滚的容器，否则超出部分根本看不到。正计时那张卡的时钟与说明文字间距从 8px 提到 16px，
  行高 1.7，卡片宽度显式给到 720（原来被 auto 边距缩成「贴着一行说明文字」的 459，字几乎顶到边）。

### 24.3 偏离与取舍（主动标注）

1. **整页视觉是自己定的**：参考站没有这一模块，无「1:1」对象。配色沿用主色绿（`--brand`）、
   番茄休息用灰字弱化，类型占比三条柱子用 绿/橙/蓝（`--brand`/`--todo-fill`/`--quad3`）。
2. **休息不计专注时长**是他选的定义，代价是「一次番茄 6 轮」在数据里只报 6×25 分，
   界面上用 `RestSec` 单列一行「其中休息 …（不计入专注时长）」说明白。
3. **补记没有真实时刻**，所以时段矩阵与日统计的小时条对它无能为力——内核把这部分单列出来，
   界面写「另有 N 条补记（…）没有真实时刻，不落在时段矩阵里」。这是数据诚实，不是漏画。
4. **番茄一轮走完就自动结算**（最后一轮之后不再休息）；参考站没有对应物可对照，按常见番茄做法。
5. **沉浸页退出（右上 ×）不结束专注**：记录留在进行中态，回到子模块时顶部出现「上次…还没结束」提示条，
   点回去继续。这样「关掉界面」和「结束专注」是两件事，不会误记一条 0 秒的记录。
6. **心得的保存口径（2026-11-08 按反馈改）**：结算页点「保存」= 落库 + **回到开始专注那一屏**，
   结算页不是要停留的地方；「返回」与右上 × 只在心得有改动时静默存一下再走。
   之前这里同时挂了「失焦即存」，于是点保存会先触发 blur 的那次写、`busy` 闸门把按钮那次吞掉，
   看起来就是「点了没反应」——现在结算页不做失焦保存，只有详情页保留「失焦即存」
   （那是个长期停留的编辑面，语义不同）。实时记录的 `FocusSave` 只认心得与关联任务两处改动，
   所以怎么存都不会顺手改坏事实字段。

## 25. 法定节假日与调休：数据源与「班/休」角标（2026-11-08）

参考站取证（`docs/reference-zomoplan.md` 第 42、58 行）：日期选择器的格子里除农历、节气、节日外，
还标 **班 / 休** 两枚角标；重复规则里有一条「智能跳过法定节假日」。
本项目此前只有 `repeat.HolidaySource` 接口、没有数据，所以两处都是空的：
角标不画（`LunarCell` 只给 `weekend`），「法定工作日」静默退化成普通周一至周五。

### 数据

`internal/core/calendar/data/<year>.json` 内置 2025 / 2026 / 2027 三年，逐条核对国务院办公厅通知原文：

| 年份 | 文号 | 公布 | 放假 | 补班 |
| --- | --- | --- | --- | --- |
| 2025 | 国办发明电〔2024〕12 号 | 2024-11-12 | 28 天 | 5 天 |
| 2026 | 国办发明电〔2025〕7 号 | 2025-11-04 | 33 天 | 6 天 |
| 2027 | 国办发明电〔2026〕10 号 | 2026-11-05 | 29 天 | 5 天 |

原文里每天都括注星期（如「2月15日（农历腊月二十八、周日）」），照它反推一遍才敢写进表。
`calendar_test.go` 的 `TestBuiltinTablesAreValid` 按「条数 + 补班必须落在周六或周日 + 出处与核对日期非空」
校验，抄错一天就会红；`TestBuiltinSpotChecks` 再点验长假首尾与补班日（含 2026-02-15 除夕、
2027-06-09 端午只放 1 天这种容易记错的形态）。

口径选择：

- **内置 + 本机整年覆盖**。`calendar.Open(dataDir/calendars)` 先铺内置，同名年份的
  `<year>.json` **整年替换**而不是叠加——叠加会让用户改掉的假日仍然被内置的那份标成「休」。
- **表没覆盖的年份不猜**。2028 年及以后 `Mark()` 返回空，「法定工作日」退化成周一至周五；
  这是有意的：拿今年的安排猜明年会算错打卡与逾期，而用户看不出被算错。
  设置页「节假日与调休」把覆盖年份、休/班条数、出处、核对日期、导入目录全部摊开，
  并写明「表没有的年份不标班/休…程序不替官方猜日历」。
- **坏数据必须当场报错**。`calendar.Write` 里做 `Validate()`（年份范围、日期格式、跨年、
  同一天既休又班、补班不在周末、空表），界面「导入」、CLI `plando calendar import`、脚本三条入口都过同一关。
  静默收下坏表 = 节假日规则悄悄失效，是最难查的那类 bug。

### 界面

- `LunarCell` 新增 `mark`（休/班/空）与 `markSource`（该年出处）。
- **日期面板**（新建/详情弹窗的月历）：角标绝对定位在格子右上角（10×10px，`top/right: -1px`），
  不进农历位——那天往往同时有节日名和农历，两个词会把数字挤掉。休=提醒红、班=中性灰，
  选中格（实心绿底）角标转白字白底。tooltip 里写明「法定节假日/调休上班 + 出处全文」。
- **月视图**抬头：角标内联跟在日期后面（抬头只有 24px，绝对定位会被 `overflow:hidden` 切掉）。
- **周视图**抬头：46px 里已经排了周几/日期/农历三行，再加一行会把农历位挤到网格上，
  所以这里也走绝对定位（`top:3px; right:5px`）。实测溢出量从 +13px 回到基线 +7px。
- **浏览器 mock** 同步内置同一份表（`api/mock.ts` 里 `HOLIDAYS` / `MAKEUP_WORKDAYS`），
  两边口径一致；注释写明「改 Go 侧那份要改这里」。

### 内核行为（数据接进来之后才真正生效的三条）

- `Repeat.SkipLegalHolidays`：命中法定假日不生成实例。
- `Repeat.FollowMakeupWorkday`：调休上班的周末在周几筛选**之前**放行（否则「法定工作日」会漏掉被要求上班的周六日）；
  只作用于按天/按周规则，每月 24 日这类不会被补班日撑出实例。
- 提醒：`UpcomingReminders` 走同一套展开，所以「法定工作日 + 每天提醒」的事项在国庆七天不会弹。
  `service/holiday_test.go` 三条测试直接用内置表（不是 fake 日历）验这三件事。
