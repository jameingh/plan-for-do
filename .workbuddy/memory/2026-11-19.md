# 2026-11-19 工作日志

## 修复 CI run #20 的两个界面自检失败（check-account / check-stat）

CI 失败在 commit 8a6d401，两个失败都是**自检脚本没跟上当前设计/种子**，不是产品功能回归：

1. `check-account.mjs`「菜单贴在左栏右侧」断言 `left > 64`，但 CSS `.avatar-menu` 有意 `left:12px`
   让开头像（global.css 有注释）。实测 `left:12 / top:46 / w:150`。断言改为校验
   `left∈[10,20] && top∈[36,60] && w===150`，名字也改掉。
2. `check-stat.mjs` 写死「今天该打 2 个 / 50%」，但种子里「跑步=每周二」，CI 恰好周二跑，
   实际 `今天该打 3 个，已打满 1 个 → 33%`。改为按内核真值动态算：读 DB 的 habits.freq
   （kind 1/2/3/4/5/6 全列，口径对齐 internal/core/service/habit_stat.go 的 due 判定）
   + clocks 当日量 + dailyTarget，算出 dueToday / doneToday / expectedPct 再比对界面。

**验证**：
- 重建前端+exe，`bash scripts/verify-restart.sh 9256 habits && bash scripts/seed-stat.sh` →
  `node scripts/check-stat.mjs 9256`：45/45 全过（周四场景，应打 2 个/50%）。
- 构造「应打 3 个」场景：把隔离库里跑步 freq 改到今天(周四)，重启实例后重跑 → 45/45 全过，
  CDP 直读显示 `33% | 今天该打 3 个，已打满 1 个`，证明动态断言在周二分支也对。
- `bash scripts/verify-restart.sh 9256 list && node scripts/check-account.mjs 9256`：33/33 全过。
- 探针实例由后续 verify-restart.sh 的 taskkill 正常结束，临时库 tmp/vdata-probe 已清理。

**结论**：改动只涉及 `scripts/check-account.mjs` 与 `scripts/check-stat.mjs`，未动产品代码；
这两个断言以后不会再因星期几或有意设计而假失败。CI 下次 push 即可转绿。

**教训**：自检脚本里凡涉及「相对今天」的期望值，必须从种子数据动态算出来，不能写死数字——
写死时脚本只在特定星期通过，CI 隔天跑就挂，而且本地复现不到。
