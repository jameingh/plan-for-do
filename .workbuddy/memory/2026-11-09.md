## 17:00–17:25：修复「点击同步报错 invalid character 'p'」并实机走通

- 报错原文：`sync: 写回 我的飞书云盘: feishu: 发布新快照失败…: feishu: 解析
  /open-apis/drive/v1/files/<token>/rename 响应: invalid character 'p' after top-level value`。
  **根因**：飞书云盘 v1 根本没有改名接口，该路径实测 `HTTP 404` + 纯文本 `404 page not found`；
  Go 把开头的 `404` 当成 JSON 数字顶层值，后面的 `page not found` 的 `p` 触发语法错，
  把「接口不存在」彻底掩盖。官方文档页也查无此 endpoint。
- 真实 API 对照结论：同名文件**可重复上传并存**（两次拿到不同 token、列目录两份都在）；
  `PATCH /files/{t}`、`POST /files/{t}/copy` 返回 400 field validation（接口存在但字段不对），
  `/rename`、`/metainfo`、`/title` 都是 404。**结论：彻底去掉 rename**。
- 新覆盖写：列目录收集旧同名 + 历史临时残留 → 以正式名直传 → **再列一次目录**
  （把并发期间另一轮写入的同名副本也纳入清理）→ 按 token 精确删旧。
  二次列目录不能省：引擎在 `pushed=0 / revision≠0` 时整轮跳过 Save，重复文件会永远留着。
- 删除做成幂等：并发覆盖写时另一轮可能已删掉同一 token，飞书回 `1061001` /
  `1061007`（顺序重复删是 1061007，不存在是 1061003 + HTTP 404）。删失败后复查列目录，
  文件已不在即视为成功；历史临时残留删不掉一律降级为不阻断（只影响云盘卫生）。
  `Probe` 的探针清理也改成尽力而为：上传成功已证明可写。
- `client.go` 的 `callJSON` / `callRaw`：非 2xx 不再盲解 envelope，先按状态码给明确诊断
  （能解出飞书错误体报 `HTTP xxx (code=…): msg`，否则报 `HTTP xxx（响应不是飞书错误体）: "片段"`）。
  新增 `responseSnippet` 截断 200 字节，避免把整份响应塞进 UI/日志。
- **UI 误导修复**：`SyncNow` 失败时内核仍发 `sync:done`，前端无条件弹绿色「同步完成」
  （用户截图同时出现红黑错误 + 绿字）。现在 `api.go` 只在 `err == nil` 时发事件；
  `wireEvents` 区分 `Result.skipped`（只有「本地无待推送内容」是正常跳过，其余按失败 `toastErr`）；
  设置页 `syncAll` 不再重复弹 toast；结果区文案区分「跳过：」与「失败：」。
- 测试：`fakeDrive` 去掉 rename 支持改成 404 护栏 + `renameAttempts()`；新增
  `TestDriveSaveUsesOfficialNameWithoutRename`、`TestCallJSONReportsPlainText404`、
  `TestDriveSaveToleratesConcurrentAndLeftoverDeleteFailures`、`TestDriveSaveConvergesConcurrentDuplicates`；

## 同一菜单的第二个 bug：选中行溢出菜单框（20:5x，CSS 类名撞车）
