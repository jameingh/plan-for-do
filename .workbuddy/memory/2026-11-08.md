# 2026-11-08

## 附件字节同步（可选 BlobChannel）

- 新增 `internal/core/sync/blob.go`：`BlobChannel{LoadBlob,SaveBlob}` 可选接口、
  `BlobArchive`（JSON + base64 + sha256/size）、`BlobArchiveFileName = planfordo-blobs.json`、
  `MaxBlobBytes = 14<<20`（原始字节；base64 后约 18.7MB，受飞书 `upload_all` 20MB 卡口）、
  路径压平防穿越、版本号与超限校验（读写两侧）。
- `Engine.Run` 在 **记录 merge 之后** 调 `syncBlobs`：拉归档 → 补本地缺失/半截字节 →
  本地独有字节并回归档 → 写回前二次 Load 只补不删（缩小 read-merge-write 窗口，残留靠下轮自愈）。
  字节通路失败只写 `Result.BlobsSkipped`，不阻断记录同步；不实现接口/未注入 dataDir 时整条跳过。
- `NewEngine/NewManager(db, dataDir...)` 用可选参数兼容旧调用；`api.go` 与 CLI `sync` 传真实 dataDir。
- 实现范围：localdir（原子写抽取 `writeRaw`）、webdav（同目录 GET/PUT，不碰快照 ETag 缓存）、
  feishuDrive（先 Tidy First 抽 `driveObject{fileName,tmpPrefix,label}`，快照与归档各有独立临时前缀，
  避免覆盖写互相清理；错误文案用 label 保持既有诊断不变）。**feishuBase 明确不支持**（表格无二进制语义），
  代码注释 + 测试护栏 + 文档写清，不是待办。
- 测试：`blob_test.go` ×3（sync 端到端两设备/坏校验/半截文件/穿越/超限/协议；webdav 往返且
  快照条件写不受影响；feishuDrive 快照与归档隔离 + Base 不支持断言）。`go test ./...`、
  `go build . ./cmd/plando`、前端 `tsc --noEmit` 全通过。
- 注意：`go build ./...` 会在 `build/ios` 报 `function main is undeclared`（main_ios.go 带 ios build tag，
  既有结构问题，与本次改动无关）；验证请用定向 build 或 `go test ./...`。
