## 习惯情境「打卡显示」开关（新增功能）

需求：情境管理里每个情境加开关，关闭后每日打卡页不展示该情境。

实现要点：
- 数据模型：`model.HabitContext.Hidden bool json:"hidden,omitempty"`，**反向语义**（零值=false=显示），老数据不带字段时行为不变，无需 migration（entity 存 JSON blob）。`HabitContextInput` 同步加 `Hidden`。
  - ⚠️ `SaveHabitContext` 是整条覆盖：编辑/改名时必须把 `hidden` 原值带回，否则会被重置为显示。前端 `rename` 和 `toggleVisible` 都已带入。
- 过滤位置：`HabitsPage.tsx` 的派生选择器 `orderedCtx`（`view.contexts` 按 `contexts.find(c=>c.hidden)` 过滤）。`flat`、键盘导航（↑↓、数字键跳组）、渲染循环、空状态全从它派生，一处过滤就不会「看不见但键盘能选到」。
  - **没有复用 `hideHabitContexts`**：那个字段同时驱动日历网格（ViewsPage），复用会让关掉的情境在日/周/月视图里也消失，超出需求范围。也没有在后端 `HabitMonthView` 过滤（同一接口还被 ViewsPage 取 rowsByContext，且会有 contexts 异步加载的闪烁）。
- UI：复用 `.hm-switch`（真 button + `role="switch"` + `aria-checked`），独特 `aria-label="在每日打卡中显示情境 X"`，避开 `.vc-sw.is-on` 全局计数和 `hm-switch` 无文字定位的雷区。全部情境（含「全天」）都可开关，只有删除仍禁止「全天」。
- 全隐藏时空状态改成提示「所有情境都已隐藏，请在「情境管理」里打开显示开关。」，而不是误报「还没有习惯」。

改动文件：`model.go`、`service/habit.go`、`types.ts`、`mock.ts`、`HabitsPage.tsx`，以及 `wails3 generate bindings -f "-tags production" -clean=true -ts -i` 重生成的 3 个 binding 文件（其中 sync/models.ts 顺带带入了之前就存在的 blobs* 字段漂移）。

## 环境坑（本次踩到）

- `scripts/verify-restart.sh` 用 `&` 起 exe 后脚本就退出；作为受管后台任务调用时，**脚本一结束，它 fork 的子进程会被回收**（CDP 曾通、随后进程消失）。正确做法：先让脚本清库/重建，再用 `run_in_background: true` **直接**把 `bin/planfordo-verify.exe` 作为后台命令启动。
- WebView2 CDP：`Runtime.evaluate` 返回 DOM 元素（`document.querySelector(...)`）会报 `Object reference chain is too long`；必须返回布尔/字符串/JSON 字符串（`!!document.querySelector(...)`）。
- 顶栏两个 `.btn.small`，`at(".btn.small")` 会取到「新建习惯」而不是「情境管理」；按文字过滤（`at(".btn.small","情境管理")`）。

## 设置页改成分组标签页

用户嫌设置页乱（5 个小节竖排、同步通道要滚到底），改成顶栏 3 个 `.gtab`：**偏好设置**（默认）/ **系统信息**（运行环境 + 节假日与调休）/ **数据与同步**（备份与恢复 + 同步通道）。

关键取舍：
- 5 个 `.set-block` **全部留在 DOM**，只加 `hidden` 属性切显隐，不用条件渲染。这样 `check-account.mjs` 按 `.set-block` innerText 找小节、`check-habit.mjs` 按 `aria-label` 找控件都还能找到，脚本改动最小。
- ⚠️ `.set-block { display:flex }` 会盖掉 `hidden` 的 UA `display:none`，必须在 CSS 里显式补 `.set-block[hidden] { display:none; }`，否则全部小节仍可见。
- `hidden` 元素的 `innerText` 在 Chrome 里等于 `textContent`，所以「找小节标题」的断言不受影响；但 `clickAt` 的 `scrollIntoView` 对 `display:none` 无效，必须先切 tab。
- 切 tab 时 `page-body.scrollTo({top:0})`，别把上个分组的滚动位置带过去。

自检脚本同步加了 `settingsTab(label)`（点 `[aria-label="设置分组"] [role=tab]`）：`check-mask`（数据与同步）、`check-account`（系统信息 / 偏好 / 数据与同步，且文本规模基线前先切回默认偏好）、`check-habit`（偏好，两次）、`verify-channel`（开头就切数据与同步，因为清通道循环也要用）。

验证（CDP 9257，隔离库）：三 tab 切换后 `visible` 小节分别为偏好 / 运行环境+节假日 / 备份+同步，`hidden:3`，`scrollTop:0`，截图肉眼确认。`check-mask` 23/0、`check-habit` 66/0、`check-account` 32/1（唯一失败是既有的头像菜单 left:12）、`check-popup` 18/0/1skip、`verify-channel` 走通（末尾 article 读数是既有过时选择器，body 文案证明通道已建并同步）。

- `cu.py find --text "系统信息"` 在这版 WebView2 上返回 no channel matched（UIA 拿不到 gtab 文本）；切 tab 用 CDP 真鼠标更稳。
